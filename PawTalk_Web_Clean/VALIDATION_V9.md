## 用户机器的最后验收

保留已有模型和配置升级后，运行 `00_START_APP.bat`，确认标题 Intent v9.1；上传一段未看标签、可描述真实观察的狗叫。核对场景八类、情绪六项分数和 usable 后，生成意图、开始问答、回答一次不知道，再提供明确观察或纠正，最后查看并导出记录。

如果页面显示 blocked，请根据具体错误运行 07/08 或检查原来的缓存；不要用固定结果绕过缺失模型。如果 DeepSeek 返回结构错误，重试当前阶段，不把报错当成模型已经完成了推理。

本版实现的是更严格、可追溯的探索流程，不承诺准确率/F1 提升到 0.6。

## v9.1 本次新增验证

针对用户 Windows 日志中的 WinError 10053，新增 11 项测试：

1. 模型仍在执行时上传立即返回 202，并可查询场景已完成的部分结果。
2. 真实本地 HTTP 连接确认先返回任务 ID，之后以新连接读取已保存结果。
3. 活跃任务的同一音频重复上传复用任务。
4. 后台异常保存为 failed，不伪造模型结果。
5. 重启后未完成任务标记 interrupted；已完成任务保留。
6. 第三个并发任务明确拒绝，避免无限创建推理线程。
7. 注入浏览器断连后，后台仍完成并保存记录。
8. 响应头/正文分别注入断连，均不向同一连接重复发送 500。
9. 数据集同名文件在加载 Runtime/CLAP 前拦截。
10. 索引诊断不包含真实标签，也不单凭文件名断言是留出集。
11. 场景失败原因可在情绪分支结束前查询到。

前端 DOM 测试另覆盖阶段/秒数显示、后台上传轮询、保存任务 ID、恢复查看与完成后清除任务 ID。真实浏览器视觉/设备测试仍受此前环境限制，未重新宣称通过。

断连测试是在此环境注入对应 Python 连接异常及执行真实本地 HTTP，不等于在用户 Windows 安全软件或网络环境复现。用户这次实际日志证明 v9 已读取索引、实时配置和情绪配置；本次助手端回归仍用模拟模型输出，不宣称已经在用户机器验证完整识别链路。
