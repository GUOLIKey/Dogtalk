# v12 描述优先的三问解释流程

## 怎么使用

1. 在文本框写当时发生的事，以及你想知道的问题。可以写“我的狗看向厨房，趴在地上哼唧，这是怎么回事？”，也可以留空；不要按已知数据集标签编造背景。
2. 上传或录制音频。原场景 8 类和情绪 3+3 类完整保留。
3. 点击“综合录音与描述，回答我的问题”。一次点击会先生成内部候选并解析描述/问题，再自动核查，不需另外点击首问按钮。
4. 有具体观察支持且能比较说明原因时直接解释，可以零次追问。其他候选无需全部排除。信息不足时逐次追问，每次一个未知事实。
5. 整段音频最多三次追问，明确重新生成也不恢复预算。第三个回答后必须结束；如果仍不足，显示当前仍合理的最多三种可能、依据和缺失信息，不强行凑满三种。

原始场景预测可能不准确，用户直接观察可以改变最终解释，但不覆盖/重训原模型。未看到、不知道、猜测及用户指令不应当作证据。“看厨房”不自动等于讨食；模型两路分数不是独立概率，也不会乘起来当意图概率。

## 结束标准

没有“超过 50% 就回答”的门槛，也不把 LLM 自评分数伪装成正确率。context-first-v1 采用可检查条件：所选候选为 supported 且有有效直接观察引文；没有保留的反证引用或未解决的关键矛盾；对所有其他候选给出相对适合程度的比较理由。比较理由仍是语言模型判断，后端不宣称完全验证语义。最终用“当前更可能”回答用户问题，并保留尚未排除的解释。

只有模型线索、规则优先项、用户猜测不足以触发主要结论。证据不足、存在矛盾、三问用尽时允许多个可能或不知道；全被排除时说明候选范围不足。

## 实际改动与结构

- dialogue.py：MAX_QUESTIONS=3；提示词版本 intent-interview-4.0；生成阶段返回 request_understanding；正常新流程自动进入评估；更宽松但有来源约束的结论门槛；最终解释及有序 alternatives。
- context_policy.py：用户问题及观察/猜测拆分的原文来源核对；readiness 中的 critical_conflicts 与 comparisons；不是概率计算。
- intent_system_v4.txt：描述优先、直接回答用户问题、提前结束、禁止一问塞多个行为、避免重复已知信息的运行时提示词。
- server.py：正常网页请求带 flow=context_first；生成和首次评估在同一次业务请求中完成，失败不会提交假结果或扣问数。保存 context_first、request_understanding、pre_observations、实际提示词版本、共享预算、原始双路分析与候选快照。旧会话 v3 结构仍可读。
- static/index.html / app.js：文本框明确接受描述与问题；一次综合分析按钮；候选依据默认折叠；优先显示解释/下一问，最终不确定时显示最多三种解释。前端与后端版本不同会阻止继续提交并显示提示。
- start_app.py：保留完整性检查并核对启动器与后端版本。
- test_context_first_v12.py：13 项专项测试，其余既有测试继续运行。

初始生成使用两次内部 LLM 调用：第一次解析问题并形成候选，第二次综合核查并给解释/首问；两次都收到完整且按实验方案裁剪的原模型信息。不是把声音最高类翻译成意图。网络/格式问题仍有有限恢复，实际等待时间由本机模型和 API 决定。

request_understanding 保存 user_question、question_quotes、statements（原文 quote、answer_id、kind=observation/guess）。问题句不会被当作行为观察。pre_observations 保留原文，observation_quotes 标记可用观察片段。语句类型由 LLM 解析，不因原文存在就证明解析正确。混合否定/过去/猜测仍有保守过滤，可能需要澄清。

最终 result 保存 explanation、readiness、policy=context-first-v1、alternatives、confidence_note；初始模型分数、摘要与规则保持不变。问题更正可撤回结论，并保留修订。旧记录延续其原过程；建议新上传录音体验新流程，旧版严格排除结果和新版描述优先结果不要混用作同一实验。

## 验证与未完成的真实联调

110 项 Python unittest 通过；Node 网页 DOM/交互契约、8 项麦克风生命周期测试通过。专项检查包括：

- 原描述和问题进入第一次模型调用，8+3+3 原始分数完整保留。
- 描述充分时零追问解释；回答一次后也可结束，其他候选仍 possible。
- 缺观察、猜测、关键矛盾、缺比较理由时不能冒充主要结论。
- 三问后无第四问；返回按当前线索排序的最多三项而非概率。
- 明确更正可撤回结论，重复请求不扣问数，首次第二步 API 失败不提交半成品。
- 旧来源别名/引用、上传后台任务、数据隔离和安装器检查继续回归。

这些模型输出与 API 返回均为模拟；没有真实 API 调用，没有实际加载用户权重，也没有测得真实意图准确率。DOM 测试不是浏览器截图或 Windows 实机验收。打包后检查源码哈希及 --check 启动。
